# 研究复核表

采集器输出：`universe.json`财报目录、`universe_current.json`当期ST板块名单、`collection.json`逐股采集状态、`companies/代码.json`材料、`raw/`请求和原始响应。研究脚本生成HTML、CSV、JSON；这不是自动预测模型。

Agent对每家公司核对主要实施依据和最新进展后，用代码为键写入 `reviewed_notes.json`。允许覆盖的研究字段例如：

```json
{
  "600000": {
    "onset_display": "YYYY-MM-DD（若为*ST转ST需注明）",
    "reasons": ["内控非标"],
    "conditions": ["实际适用撤销条件及板块"],
    "achieved": ["已落实的事实，注明材料日期与证据强度"],
    "pending": ["尚缺的审计或实质整改条件"],
    "level": "等待年度审计验证",
    "window": "条件成立时可能的窗口；无依据时明确无法定期",
    "reasoning": "综合判断，说明支持证据、剩余约束和失效条件",
    "review_status": "研究者复核：具体核验范围，仍未确认的事项",
    "additional_sources": [{"date":"YYYY-MM-DD","title":"正式材料","url":"https://example.com/filing","quote":"支持判断的短摘录"}]
  }
}
```

上例代码为格式占位，不能作为真实分析导入。不要覆盖原始数据或把没有核对的股票标成已复核。`reasons`的内置类别包括处罚/虚假记载、内控非标、资金占用、违规担保、账户冻结、经营/持续经营、分红不达标；更具体的原因写在条件和判断中。

建议按“整改接近完成候选、未来90日条件型候选、处罚满期观察、经营改善观察、等待年度审计验证、实质障碍待消除、待补证据、已申请、已退出/已获批”组织，标签是研究分类，不是经过统计校准的概率。未来90日须有实际日期依据及整改支持；只知道戴帽日不够。

重点检查：

- 原因是否对应仍有效的本轮警示，而非已撤销的旧案。
- 是否把半年归母扭亏误当扣非盈利或年度审计通过。
- 是否把公司自述整改完成误当会计师意见。
- 占用款是否真正到账，担保是否真正免责，冻结是否实际解除。
- 收件日是否被误当作出日；公告中的“满12个月”条件引用是否被误当事实。
- 已撤销部分警示、已申请及已获批是否与申请前候选分开。
- 正文是否截断，未读末段是否可能含新增条件。

交付前核对名单数=表格行数+明确排除/失败数；每行保留来源，缺证据的判断降级。若用户要求全量，不以抽查几家公司替代。


## 原因到撤销路径的字段

`trigger_detail`记录具体戴帽事实；`operating_subtype`区分“连续亏损并持续经营不确定性”“生产经营严重受影响”或具体待核情形，不能只因财务亏损就赋值。`removal_thesis`解释为何可能撤销/为何申请，`remaining_barriers`说明尚缺项；已申请或获准公司也必须填写。

渲染器派生`board/rule_analysis/rule_route/profit_relation`，将仍有效或申请所涉原因映射至该板块条款。这是条件解释，不是满足认证。`latest_profit_status/annual_profit_status/profit_warning`独立描述财务及经营风险；`profit_gate`仅用于投资偏好筛选。

可人工复核`readiness/window_start/date_basis/catalyst`以控制证据状态和排序窗口。正式决定作出周年、收件日估计、审计季情景与公告确定生效日不能混用。`status_evidence`保留最新决定来源及实际公开时间、正式公告日期，`effective_date`为已披露生效日。最新完整撤销决定优先于旧人工“已申请”标签；较早年度的历史摘帽不能覆盖重新戴帽。

默认呈现申请前、已申请待审核、已披露决定待生效/已生效三个区，并保留全量表。每个区直接显示本轮ST时间、实际原因、适用规则、撤销路径、剩余障碍及财务风险。原因不明就保留待核，不把宽泛“未披露”强塞进处罚12个月路径。
