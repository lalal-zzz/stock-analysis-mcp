# A股分红公告与日期

用结构化分红数据做批量筛选，用正式公告核实日期和方案变更，用新闻发现线索。不要仅靠新闻搜索声称查完所有股票。查询不授权修改交易账户、行情库、回测复权或创建定时任务。

## 日期与默认含义

“最近分红”未指定含义时，同时给最新已公告方案和最近已到除权除息日的现金分红，把未来已确定日期另列为待实施。使用用户时区及当前日期，明确抓取时间。

- 预案公告日：提出方案，通常不能据此确定登记或到账日期。
- 最新公告日：数据商记录的最新方案公告，不自动等于实施公告日。
- 实施公告日：发布具体权益分派安排；从原文或明确接口字段取得。
- 股权登记日：权益登记日期，不是除权日或支付日。
- 除权除息日：价格除权除息日期，不是现金到账确认。
- 派息日：支付安排日期；缺字段就写“待公告核实”，不能用除息日替代。
- 报告期：利润所属期，不能当作实施年份或公告日期。

## 来源与执行

首次查询读取 [references/sources.md](references/sources.md)，其中包括已核实接口、字段差异和覆盖边界。

单股使用结构化历史详情并核实最新实施/更正公告，依据明确交易所标识区分沪深北A股与B股、H股、基金和优先股，不能仅凭代码猜品种。

全市场先取得有来源、日期、交易所及证券类型的当期上市A股名单，包含北交所；按报告期或公告日期批量拉取，完成分页，再与名单联查。每股给最新公告事件、最近已到除息日的现金分红和即将实施事件。未匹配标为“该查询范围未发现记录”，不能写“从未分红”。只有若干报告期而没有名单及全量历史时，明确称为“这些报告期的分红记录”，不声称全A股最近一次完整覆盖。

最近消息搜索“利润分配预案/权益分派实施公告/分红/更正/调整/取消”。优先公司、交易所及巨潮正式公告，读取原文日期和方案；媒体标题仅为线索，不将计划、股东大会通过和实施分配混为一谈。

无第三方依赖的脚本读取东方财富公开网页数据接口，查询明确报告期或单股历史并归档原始JSON及元数据；不采集新闻原文，不自动完成名单联查或公告核验：

```powershell
python <skill-dir>/scripts/fetch_dividends.py --period 20251231 --period 20260630 --as-of 2026-10-08 --output <output-dir>/dividends-20261008.json
python <skill-dir>/scripts/fetch_dividends.py --symbol 000001 --as-of 2026-10-08 --output <output-dir>/000001-dividends-20261008.json
```

示例日期按实际查询更新。默认最多40页/请求；超限、接口错误或分页不一致会失败，不把截断结果当成功。超时最多重试一次，不绕过认证或反爬限制。正常返回也不证明覆盖沪深北所有证券。使用新文件名留存快照。

## 核验与输出

展示代码及交易所、名称、报告期、方案原文/含税金额单位、方案进度、公告日、登记日、除息日、派息日、原始公告链接及抓取时间。按最近公告日或明确日期排序，并说明排序依据。公告日超过用户截止日期的记录不得当作截止时已知消息，标为“来源含截止日之后的日期，需核实”，保留原始值。金额区分每10股与每股、含税与税后；未确认时保留原字段及原文，不自行换算。

保留不同报告期和同年多次分红，记录修订/取消；正式更正公告优先但保留旧版本。同股同报告期可能有多次分红，不仅按这两项去重。数据商日期与公告冲突时展示冲突并以正式公告为准。预案没有确定日期就留空，不推测。实施安排且除息日在过去只说明“已到除息日”，不证明到账。

全市场报告名单证券数、匹配数、无记录数、失败数、所查询报告期及分页状态；北交所缺失或未验证时明确标注。引用可打开的正式公告或数据页面，不只链接搜索结果。

## 历史回测边界

最新网页是当前可得修订快照。按公告日过滤也不证明当年的字段当时已公布，后补登记日/除息日不能归到最早预案公告日。需要公告原文、发布时间、采集时间及版本，才能建立逐字段可知时间。

该skill提供分红查询，不宣称解决完整复权。账户仍需现金红利、送转、配股、特殊权益分配、股本基数、支付/上市时间及税费处理；不得据此直接更新复权因子或回测账本。
