# 普通ST未来摘帽研究

目标是在申请公告前，依据已公开事实判断“剩余什么条件、何时可能满足、什么证据会推翻判断”。公告是证据来源，输出应是逐家公司条件分析，不只是公告列表。

## 名单与材料

先读 [sources-and-rules.md](references/sources-and-rules.md)，按板块和实际原因查阅 [撤销条件与盈亏关系](references/removal-rules-2026.md)。默认研究简称以ST开头的沪深A股，排除*ST、B股及已摘帽公司；用户要求扩大范围时单列处理。北交所必须另核名单和规则，不把沪深板块口径称为沪深北全覆盖。

使用当期东方财富ST板块完整分页名单，保留代码、市场、名称、抓取时间、总数和分页校验。以完整财报目录交叉核对，再逐股核实当前简称。名单失败时可以继续有界研究，但明确范围和漏项，不能用最近几天有公告的公司替代全体ST。

技能脚本位于 `scripts/`，在项目内自动定位现有网络层；安装到别处时提供 `--project <项目根目录>`。每次实时更新使用新输出目录；同目录用于恢复同次归档，不代表重新抓取了实时数据。

```powershell
python -X utf8 <skill-dir>/scripts/st_research_collect.py --output <新报告目录>
python -X utf8 <skill-dir>/scripts/st_research_report.py <报告目录> --as-of YYYY-MM-DD --overrides <逐家复核JSON>
```

采集器归档原始响应及逐家公司材料，报告脚本只做规则初筛。Agent须读取关键原文并逐家公司复核后填写覆盖字段，格式见 [research-table.md](references/research-table.md)。不要把脚本生成的初筛标签改名为人工已核验。

长公告正文接口按约5000字分块，必须检查 `page_size` 并逐块读取；`body_complete=false` 不是全文。缺少关键末段时补取对应分块或正式PDF，不能根据首页缺少某句就断言条件未满足。优先原实施公告、最新继续/叠加/部分撤销公告、正式处罚决定、更正专项报告和相关审计意见；股吧仅作为待核线索。

## 逐家公司判断

- 列明本轮戴帽的实际原因及适用板块。正文引用一整串监管条款，不代表公司同时触及全部条款；虚假记载免责声明也不是造假事实。
- 区分首次历史戴帽、本轮重新戴帽、*ST转ST和叠加警示的日期，停牌日不能替代实施日。跟踪每一项原因的新增、消除和仍有效状态，不将已撤销历史事项重复列作当前障碍。
- 对每项有效原因，分别写“已有证据、未满足、尚待核实”。制度修订、还款计划、起诉和股东承诺不等于整改通过、清偿到账或担保免责；公司自述和会计师/律师意见分开。
- 处罚类核对最新本轮正式决定的作出日期、追溯重述覆盖年度、专项核查及适用的投资者索赔计提要求。满12个月是其中一项申请条件，不从事先告知书或戴帽日起算。只核实收件日期时给近似月份并标明，不能声称已确认精确最早申请日。多次处罚须逐案匹配。
- 内控类核对最近年度内控审计、整改有效运行、意见涉及事项及后续新增问题。最新否定意见不能被更早的无保留意见覆盖。亏损/持续经营类与严重停产/经营受影响类分开；“三年不亏损”不是通用摘帽规则。归母、扣非及经营现金流可作经营证据，半年盈利不能代替年度审计。
- 有多项警示时，以全部条件为约束；部分撤销或摘星后保留ST不能归为即将全部摘帽。已申请、已获准待生效、已经生效分别列示，保留原戴帽原因、申请/获准依据及剩余风险。新披露决定优先于旧复核标签，历史摘帽公告不能覆盖本轮重新戴帽。

## 前瞻输出

使用完整对照表，至少含：公司/代码/板块、本轮ST日期、仍有效原因、撤销条件、已满足及部分落实事项、缺口、可能窗口、条件型判断、来源与核验日期。每家公司给出理由；条件不充分时说明缺的是什么，不能仅填“关注公告”。

优先继续研究两类：处罚等待期接近结束且更正已落实；资金等实质问题已解决、仅剩必要专项核查。内控和经营恢复类按实际整改和审计节奏推演，不一律排到下一年春季。时间窗口是条件情景，不是公司承诺。没有统计回测时不输出数字成功率。

若讨论股价机会，再独立检查近期除权可比涨幅、成交量、估值和预期是否已交易。研究优先级不等于买入排序，获准摘帽也不保证上涨。

报告附名单覆盖、逐股材料成功/失败、正文截断及未确认条件。全量要求必须每家公司都有记录，失败行也保留。输出HTML/CSV/JSON及简短结论，事实与推演分开；当前修订快照不能用作历史时点回测。

本技能不修改账户、持仓或交易规则，不默认创建定时任务或新增注册MCP工具。


## 排序与颜色

HTML先显示近期预期摘要、已申请公告摘要，再列全量表。默认申请前优先，按机器日期窗口从近到远；未知日期排后，已过期限不得伪装成即将到期。提供按证据成熟度切换排序和申请状态筛选。

绿：整改证据较充分、主要等期限；青：实质事项已披露解决、尚缺专项核查；黄：期限可观察但关键条件待核；蓝：等待审计/经营验证；红：实质障碍或证据缺口；紫：已有实际申请公告。每种颜色必须附文字。只有逐股原文支持才能覆盖为绿色，不能把接近满期自动判为硬条件已全部满足。

复核JSON可写 `readiness`（上述绿/青准确标签）、`window_start`（ISO日期）、`date_basis`、`catalyst`。明确日期性质为正式作出日周年、收件日估计、情景月份或未定；`window_start`只是排序键，不是摘帽承诺。对已申请者链接实际申请公告并保留审核不确定性。A/B/C/D是研究证据优先级；买入价值仍需另查价格、成交、估值及预期交易程度。


展示时必须直接列出本轮ST时间、戴帽原因、最新累计期及最近完整年度的归母/扣非盈亏与金额，不得只放进折叠详情。提供“最新一期归母、扣非均不亏损”筛选；缺失值不能视为盈利，半年报不能年化成全年。处罚整改证据与经营质量独立：颜色只表示事件条件进度；亏损使用独立风险框，不自动否定处罚/内控等路径或改变其证据成熟度。不亏损筛选为投资偏好，不是通用撤销风险警示的法定门槛。连续亏损并持续经营不确定性类须保留“年审利润达标或者持续经营不确定性消除”的备选路径，不改成全部必须盈利。


## 更新已有快照

先用新的请求归档刷新当前名单及逐家近期公告/财务/行情，再重新核对人工结论，最后渲染。渲染器不联网，重新生成HTML不能称为更新了消息。

```powershell
python -X utf8 <skill-dir>/scripts/st_research_refresh.py <报告目录> --project <项目根目录> --as-of YYYY-MM-DD --since YYYY-MM-DD
python -X utf8 <skill-dir>/scripts/st_research_report.py <报告目录> --as-of YYYY-MM-DD --overrides <逐家复核JSON>
```

刷新保留旧历史原文及新增请求归档。`since`选择上次成功核查之前并留重叠区间；不能有时间空档。检查`freshness.json`失败项和当前名单新增公司，新公司用采集器补齐后再称全量。公告按`display_time`等公开时间纳入，保留`notice_date`另作正式公告日期，避免漏掉周日已公开、落款周一的撤销决定。可见的申请前摘要、申请公司及获准公司表均须直接显示本轮ST时间和实际原因，不能只在折叠详情中保留。

仓库示例见 [2026-10-18研究快照](../../examples/st-removal/2026-10-18/README.md)。示例不是实时推荐，禁止作为可交易历史回测样本；更新时不要把示例中的公司、日期或结论硬编码为通用规则。
